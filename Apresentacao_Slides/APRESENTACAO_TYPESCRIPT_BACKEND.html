01 · Parâmetros e retorno

O contrato da função
fica visível.

backend/src/services/participants.service.ts · parseId 
private parseId(value: string): number {
  if (!/^\d+$/.test(value)
      || Number(value) < 1
      || !Number.isSafeInteger(Number(value))) {
    throw new AppError(400, "INVALID_ID", ...);
  }
  return Number(value);
}
O QUE O COMPILADOR SABE

Entrada e saída esperadas

  • value deve ser string, como o parâmetro de rota.
  • A função retorna um number ou lança um erro.
  • Uma chamada incompatível pode ser detectada antes de executar a API.

O tipo estático não substitui as verificações: o ID também é validado em runtime porque veio de uma requisição externa.

02 · Modelar o dado com interface

Descreva o dado.
Compartilhe o contrato.

backend/src/types/participants.ts 
export interface Participant {
  id: number;
  name: string;
}

export interface ParticipantsRepositoryContract {
  findAll(): Participant[];
  findById(id: number): Participant | null;
  create(name: string): Participant;
  import(names: string[]): Participant[];
  update(id: number, name: string):
    Participant | null;
  delete(id: number): boolean;
}
ONDE É USADA

Entre serviço e persistência

O repositório implementa o contrato, e ParticipantsService depende dessa interface.

Os testes também usam o contrato para tipar um repositório simulado.

Resultado: mudanças incompatíveis ficam mais fáceis de localizar.

03 · Promise e async/await

A operação assíncrona
declara o que resolve.

backend/src/services/participants.service.ts · create 
async create(
  body: unknown
): Promise<Participant> {
  const name = this.validateBody(body, true);
  if (name === undefined) {
    throw new AppError(422, "NAME_REQUIRED", ...);
  }
  await this.ensureUniqueName(name);
  return this.save(() =>
    this.repository.create(name)
  );
}
NO CONTROLLER

Await antes da resposta

Em participants.controller.ts, create retorna Promise<void> e aguarda o serviço antes de enviar o status HTTP.

A ordem fica clara: validar → verificar duplicidade → persistir → responder.

Ressalva: SQLite é acessado de forma síncrona neste projeto. O uso de async/await aparece nas operações do serviço/controlador e na API, não transforma o driver SQLite em assíncrono.

04 · Validar em runtime

TypeScript termina na compilação.
A requisição vem de fora.

backend/src/schemas/participants.schema.ts 
export const participantNameSchema =
  z.string()
    .trim()
    .min(1, { message: "NAME_REQUIRED" })
    .max(100, { message: "NAME_TOO_LONG" });

export const importBodySchema = z.object({
  names: z.array(z.unknown()),
}).strict();
USO NO SERVIÇO

safeParse antes de confiar

ParticipantsService valida o corpo e cada nome com safeParse.

  • Nome tem que ser texto não vazio.
  • Limite de 100 caracteres.
  • Campos inesperados são rejeitados.

O projeto já tem esse conceito: Zod valida em execução e os erros são convertidos para os status/códigos de resposta da API. Uma interface TypeScript sozinha não validaria o JSON.
